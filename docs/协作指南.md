## 一、拿到仓库权限（由仓库所有者完成）

仓库是公开的，**任何人都能克隆、能看代码，但只有成员才能推送**。

仓库所有者需要在 Gitee 上操作：

> 打开仓库 → 顶部「**管理**」→「**仓库成员管理**」→「**邀请用户**」→ 输入对方的 Gitee 用户名 → 角色选「**开发者**」

| 角色 | 能干什么 |
| --- | --- |
| **开发者** | 可以推送、可以建分支 ✅ 协作用这个 |
| 观察者 / 报告者 | 只能看、只能提 Issue，**推不上去** |

如果推送时报 `remote: Permission to ... denied`，八成就是没被加进来，或者角色选错了。

## 五、配置推送凭据（二选一，只需一次）

### 方式 A：私人令牌（HTTPS，最简单）

1. 打开 Gitee → 右上角头像 →「**设置**」→ 左侧「**安全设置**」→「**私人令牌**」
2. 点「生成新令牌」，起个名字（比如 `milky-frog-stead`），权限勾选 **`projects`**，生成后**立刻把令牌复制保存**（离开页面就再也看不到）
3. 之后第一次 `git push` 时会弹窗要求登录：

```
Username: 你的 Gitee 用户名
Password: 粘贴刚才的令牌        ← 注意！不是登录密码
```

Windows 的「凭据管理器」会自动记住，以后不用再输。

### 方式 B：SSH 公钥（推荐，一劳永逸，不会过期）

```bash
ssh-keygen -t ed25519 -C "你的邮箱"
```

一路回车（密码可以留空）。然后复制公钥内容：

```bash
# Windows PowerShell
cat ~/.ssh/id_ed25519.pub
```

打开 Gitee →「设置」→「**SSH 公钥**」→ 粘贴 → 确定。然后改掉仓库地址：

```bash
git remote set-url origin git@gitee.com:hong-qizhi/milky_frog_stead.git
ssh -T git@gitee.com
```

看到 `Hi xxx! You've successfully authenticated...` 就通了，以后推送完全免密。

## 六、日常开发流程

### 每次开工前：先拉最新代码

```bash
git pull --rebase origin master
```

> **不先拉就直接写，是最常见的踩坑方式**，后面推送必被拒。

### 情况一：小改动，直接推 master

```bash
git pull --rebase origin master
git add -A
git commit -m "加入青蛙跳跃动画"
git push origin master
```

### 情况二：多人同时改，走分支 + Pull Request（**推荐**）

这样你的改动先进自己的分支，由仓库所有者 review 后再合进 master，不会互相覆盖。

```bash
# 1. 从最新的 master 开一个分支，名字取有意义一点
git checkout master
git pull --rebase origin master
git checkout -b feature/种田系统

# 2. 写代码，然后提交
git add -A
git commit -m "加入种田系统的基础逻辑"

# 3. 推到远程的自己分支
git push -u origin feature/种田系统

# 4. 浏览器打开仓库页面，Gitee 会提示「新建 Pull Request」，点它，填说明，提交
```

仓库所有者 review 通过后点「合并」，改动才进 master。

### ⚠️ 铁律

- **绝对不要对 `master` 用 `git push -f`（强制推送）**，会把别人已经推上去的提交整个冲掉。
- 提交前先 `git status` 看一眼，别把不该提交的东西加进去。
- 提交信息写清楚「改了什么」，不要写「更新」「fix」这种没信息量的。

## 七、用 Godot 打开项目

1. 打开 Godot 4.7
2. 点「导入」/「Import」
3. 浏览到 `milky-frog-stead/project.godot`，选中打开

> 首次打开时 Godot 会自动生成 `.godot/` 缓存目录，**这是正常的，它已经被 Git 忽略，不会污染仓库**。

**务必所有人用同一个 Godot 版本（4.7）。** 版本不一致时，`project.godot` 里的 `config/features` 那行会被自动改写，产生毫无意义的 diff 和冲突。

## 八、本仓库的注意事项（重要）

1. **`.godot/` 目录绝对不要提交。**
   它是引擎导入缓存，每个人本地都会重新生成。已经在 `.gitignore` 里忽略掉了，你不需要管；如果 `git status` 里莫名出现了它，说明忽略规则被破坏了，请找仓库所有者。

2. **`*.import` 文件必须提交。**
   每个资源旁边都有个同名的 `.import` 文件（如 `farm.png.import`），记录导入参数，是工程的一部分，不要删、不要忽略。

3. **工程在子目录里。**
   克隆后在仓库根目录 `cd milky-frog-stead` 才能看到 `project.godot`。Git 操作在仓库根目录做，Godot 打开的是子目录里的工程。

4. **二进制资源（图片、音频、字体）尽量避免多人同时改同一个文件。**
   Git 没法合并二进制文件，一旦两个人改了同一张图，只能有一个人重做。

5. **不要提交构建产物和导出文件。**
   `export/`、`build/`、`*.exe`、`*.apk` 等都已在忽略列表里。

6. **不要提交密钥和本地私有配置。**
   `.env`、`*.local.cfg` 之类已经在忽略列表里，别用 `git add -f` 强行加进去。

## 九、常见问题排查

| 现象 | 原因 | 解决办法 |
| --- | --- | --- |
| `Authentication failed` / `403` / `token username invalid` | 令牌失效、输错、或权限不够 | 重新生成私人令牌（要勾 `projects`），推送时把令牌当密码用 |
| `! [rejected] master -> master (non-fast-forward)` | 远程有别人先推的提交，你本地落后了 | `git pull --rebase origin master` 解决冲突后再 `git push` |
| `remote: Permission to ... denied` | 你不是仓库成员，或角色只是观察者/报告者 | 让仓库所有者把你加为「**开发者**」 |
| `fatal: refusing to merge unrelated histories` | 你是自己 `git init` 再把远程接上去的，历史不相干 | 删掉重来，用 `git clone` 克隆 |
| `git pull` 时提示冲突 `CONFLICT (content)` | 你和别人改了同一处 | 手动编辑冲突文件（搜索 `<<<<<<<`），改完 `git add <文件>`，再 `git rebase --continue` |
| Godot 提示工程版本不符 | Godot 版本和别人不一样 | 换成 4.7 |
| 想撤销还没提交的修改 | — | `git checkout -- <文件>`（危险，改动会丢） |
| 想撤销最近一次提交但保留改动 | — | `git reset --soft HEAD~1` |

> 遇到搞不定的问题，**不要乱用 `git reset --hard` 和 `git push -f`**，
> 先把 `git status` 和报错信息截图发到群里问一下，多数情况都有救。

## 十、常用命令速查

```bash
git status                      # 看当前改了什么（最常用，迷路了就敲它）
git pull --rebase origin master # 拉取最新代码并变基
git add -A                      # 暂存所有改动
git add <文件>                  # 只暂存指定文件
git commit -m "说明"            # 提交
git push origin master          # 推送到主分支
git log --oneline -10           # 看最近 10 条提交
git diff                        # 看还没暂存的改动内容
git checkout -b feature/xxx     # 新建并切换到分支
git branch -a                   # 看所有分支
```
