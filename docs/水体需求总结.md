# 水体需求总结（按原始设计稿整理）

> 原始需求：水体边缘起伏动画；纹理质感交给着色器处理。
> 本文按需求原文的顺序整理，右边一列是当前实现状态（截至 `milky-frog-stead` 当前工作区）。
>
> 状态说明：✅ 按原方案做了 · ⚠️ 做了但改了做法（附原因）· ❌ 没做（附替代方案）

## 七、平台差异（原文是 Unity Shader Graph 的说法）

| 原文 | Godot 4.7 实际做法 |
| --- | --- |
| Subgraph | 没有该概念 → `.gdshader` 里写函数，或用 `.gdshaderinc` 共享 |
| Sprite 主贴图 | 地面是 `TileMapLayer`，没有 sprite alpha → 用烘焙贴图的 A 通道 |
| RenderTexture 逐区域更新 | `Image` + `ImageTexture.update()` 整张上传（160² 很小，无所谓） |
| step 节点 | `step()` / `smoothstep()` |
| 双线性开关 | `uniform sampler2D x : filter_linear;` |

## 八、踩过的坑（实现层面，值得记住）

1. **距离场不能用「高度差 ÷ 梯度」近似**——山脊处会炸出假距离，沙滩会跑到草地中间。
2. **烘焙矩形要以「区块 − 视距」为起点**，否则整张图偏移，屏幕一侧一直在采样被 clamp 的边缘。
3. **`shore_offset` 是负的**：距离场在水里为正，要往外推水线就得减，写正数水会缩进陆地被盖住。
4. **深水区的模糊值也是白的**：浪花只用「白色区域」会铺满整片海，必须再乘一道离岸距离。
5. **描边不能掺浪花纹理**，一掺就断成一节一节；描边和浅深过渡也是两件事。
6. **水线量化顺序**：先量化世界坐标再取距离，才有块状过渡；先算再量化会得到平滑糊边。
7. **像素贴图不能用平滑灰度图**：64² 硬边（有序抖动、无抗锯齿）+ `filter_nearest` 才对。
