# Milky Frog Stead 游戏企划（Demo 阶段）

> 版本：v0.1（Demo 立项稿）
> 引擎：Godot 4.7 / 语言：GDScript / 视角：2D 像素俯视
> 面向：全体开发同学。本文是 Demo 阶段的**唯一范围基准**，凡本文没写的系统，Demo 不做。

---

## 一、一句话定位

**你是老板，不是农民。**

一款「放置经营」游戏：玩家**不操作任何角色**，只负责分配员工岗位、配置每日餐厅菜单、决定钱花在哪里；
其余的一切——耕种、喂养、钓鱼、做菜、端盘子、收钱——全部由员工自动完成。

玩家每一次点击的收益，都会在几分钟后以一种"我早就种下的因"的方式回馈回来。这就是核心爽点。

### 核心体验关键词

| 关键词 | 含义 |
| --- | --- |
| 布置而非操作 | 玩家的手只碰 UI（分配面板、菜单面板、商店），从不碰角色 |
| 因果可追溯 | 钱变多了，玩家能立刻说出"因为我昨天把青蛙调去了厨房 / 因为菜单上了烤鱼" |
| 瓶颈感 | 营收卡住时，玩家要能看出卡在哪：座位不够？厨师不够？食材不够？ |
| 一天一循环 | 以"天"为最小决策单位，节奏干脆，不拖沓 |

### 参考作品与差异

| 参考 | 借鉴什么 | 我们不做什么 |
| --- | --- | --- |
| 潜水员戴夫的寿司店 | 营业时段的顾客流、上菜节奏、座位/厨师瓶颈 | 玩家不亲自下海、不亲自端菜 |
| 放置/挂机农场类 | 员工自动化、产能随时间累积 | 不做长时间离线挂机（Demo 只做游戏内速度） |
| 美食经营类 | 菜单配置 → 顾客满意度 → 营收 | 不做复杂菜谱树，Demo 只有 6~8 道菜 |

## 二、核心循环

三层循环，Demo 必须全部跑通。

```
┌─ 玩家决策层（唯一需要玩家动手的地方）─────────────────────┐
│  ① 分配员工岗位   ② 配置餐厅菜单   ③ 花钱（买/招/扩）      │
│  ④ 点击「开始营业」                                        │
└──────────────────────────┬────────────────────────────────┘
                           │
┌─ 单日循环（一天的节奏）───▼────────────────────────────────┐
│  早晨 → 员工自动上工（寻路、干活）                          │
│      → 农作物结算：昨日播种的成熟，可收获（每天一次）        │
│      → 餐厅配置菜单（读当前食材库存）                       │
│  营业 → 点击开始 → 90 秒内顾客陆续进店 → 自动上菜 → 收钱     │
│  打烊 → 结算：营收 − 食材成本 − 员工工资 = 当日净利润        │
└──────────────────────────┬────────────────────────────────┘
                           │
┌─ 成长循环（跨天）─────────▼────────────────────────────────┐
│  净利润 → 招员工（提升自动化上限）                          │
│         → 扩农场（种地/畜牧/钓鱼区域扩容，提升食材产能）      │
│         → 扩餐厅（座位/灶台，提升同时服务人数）              │
│         → 更强的员工 → 更多食材 → 更高营收 → 回到起点        │
└───────────────────────────────────────────────────────────┘
```

### 资源闭环（策划核心，必须闭合）

```
                 ┌──────── 种子 / 幼崽（花钱买）────────┐
                 ▼                                      │
  种地区域 ──作物──┬──> 直接作为餐厅食材                 │
                 │                                      │
                 └──> 饲料 ──> 畜牧区域 ──蛋/奶/肉──> 餐厅食材
                                                                │
  钓鱼区域 ──鱼──────────────────────────────────> 餐厅食材      │
                                                                ▼
                                                        餐厅做菜卖钱
                                                                │
                                                                ▼
                                                        蛙币（营收）
                                                                │
                    ┌───────────────────────────────────────────┤
                    ▼                       ▼                   ▼
              招募员工                 扩展农场              扩展餐厅
```

**闭环要点**：作物不只是食材，也是**饲料**。这条线让"种地"和"畜牧"产生依赖，而不是两个互不相干的产钱机器。

## 三、玩家操作面（Demo 全部输入就只有这 4 个）

这一节是防止范围爆炸的护栏。**任何不在下表内的玩家输入，Demo 一律不做。**

| # | 操作 | 界面 | 频率 |
| --- | --- | --- | --- |
| 1 | 把员工拖到某个岗位上（可撤下） | 员工分配面板 | 每天若干次 |
| 2 | 勾选今日菜单（受菜单格数上限限制） | 餐厅菜单面板 | 每天 1 次 |
| 3 | 花钱：买种子 / 买动物 / 招员工 / 扩地 / 扩座位 | 商店面板 | 攒够钱时 |
| 4 | 点击「开始营业」 | 主界面按钮 | 每天 1 次 |

> 明确**不**允许：鼠标点击田地收割、点击顾客上菜、拖动角色移动、键盘控制角色。
> 员工的一切行为必须是玩家配置的结果，而不是玩家的手。

## 四、系统设计

### 4.1 时间与日结算（GameClock）

- 一天 = `早晨阶段` + `营业阶段` + `结算阶段`，由状态机驱动，**非实时日历**。
- **营业阶段时长：90 秒现实时间**（Demo 数值，可调）。其余阶段无倒计时，玩家想配置多久就多久（"暂停式思考"）。
- 农作物生长以"天"为单位结算：播种后经过 N 个"早晨结算"成熟，**每天只能收获一次**。
- 提供 1x / 2x 速度切换（Demo 可选做，优先级低）。

### 4.2 农场系统（三大区域）

农场底图已有：`assets/sprites/backgrounds/farm.png`。三大区域在底图上划分子区域，各自挂载自己的工作站。

#### 种地区域（种地）

| 项 | 规则 |
| --- | --- |
| 地块 | 每块地同一时间只能种一种作物；初始 4 块，可扩到 8/12 块 |
| 流程 | 员工播种 → 每日早晨推进生长阶段 → 成熟 → 员工收获入库存 |
| 收获频率 | **每天 1 次**（同一地块当天收获后不会立刻再产） |
| 无人照料 | 生长照常推进，但成熟后无人收获 → 隔天枯萎（Demo 可简化为"不枯萎，但占着地块"） |
| 玩家不做 | 玩家的手不碰地。种子由玩家买，播种由员工做 |

#### 畜牧区域（畜牧）

| 项 | 规则 |
| --- | --- |
| 动物 | 鸡（产蛋）、奶牛（产奶），后续可加羊（产毛） |
| 需要 | **饲料**（由作物转化或直接购买）+ 员工每日照料 |
| 产出 | 每天早晨结算一次产出，投入库存 |
| 关键约束 | 无员工照料 → 当天产出减半或不产出（这是"要人"的软压力） |
| 喂养 | 员工从仓库取饲料 → 走到饲槽 → 投喂（一个完整的寻路 + 交互流程） |

#### 钓鱼区域（钓鱼）

| 项 | 规则 |
| --- | --- |
| 形式 | 鱼塘/钓点，**不是**玩家操控的小游戏（Demo 明确不做潜水/钓鱼 minigame） |
| 产出 | 按时间自动积累"渔获点"，员工定时去收网，收网得鱼 |
| 员工收益 | 无人时只按基础速率慢速积累；有人值守时速率翻倍 |
| 定位 | 餐厅高价值菜品（烤鱼）的食材来源，用来给玩家"再招一个人"的理由 |

### 4.3 员工系统（Demo 的灵魂）

玩家初始拥有 **1 名员工（青蛙）**，形象即当前工程里的 12 帧像素动画（`assets/sprites/3像素.png`，`frog_walk_left` / `frog_dle_right`）。

#### 员工属性

| 属性 | 说明 | Demo 是否需要 |
| --- | --- | --- |
| 移动速度 | 决定从 A 到 B 的耗时，直接影响产能 | ✅ 必需 |
| 工作速度 | 单次工作耗时 | ✅ 必需 |
| 体力 | 工作消耗，耗尽需回休息点恢复 | ✅ 必需（放置类的节奏阀门） |
| 日工资 | 每天结算扣钱，防止无脑堆人 | ✅ 必需 |
| 专精（农活/厨艺/服务） | 不同岗位效率不同 | ⚠️ 可选，Demo 只做数值差异，不做复杂技能树 |
| 好感度 / 成长 | 长期养成 | ❌ Demo 不做 |

#### 岗位（Job Slot）

岗位是"场景里的一个可被占用的工作点"，员工被分配到岗位后自行前往并循环工作。

| 区域 | 岗位示例 | 工作循环 |
| --- | --- | --- |
| 种地 | 地块 A / 地块 B | 走到地块 → 播种/浇水/收获（按当前地块状态决定动作） |
| 畜牧 | 鸡舍 / 牛棚 | 走到饲料仓取料 → 走到饲槽投喂 → 挤奶/收蛋 → 送回仓库 |
| 钓鱼 | 钓点 | 走到钓点 → 收网 → 送回仓库 |
| 餐厅 | 厨房灶台 | 接收订单 → 做菜（耗时）→ 出菜 |
| 餐厅 | 前厅服务员 | 取菜 → 送到对应顾客桌 → 上菜 |
| 餐厅 | 收银台 | 顾客用餐完 → 结账收钱 |

#### 员工 AI（状态机，够用就好）

```
        ┌──────────┐   分配到岗位    ┌────────────┐
        │  IDLE    │ ──────────────> │ SEEK_WORK  │
        │ 待命     │ <────────────── │ 前往岗位   │
        └──────────┘   体力不足      └─────┬──────┘
             ▲                             │ 到达
             │                             ▼
        ┌────┴─────┐   体力耗尽      ┌────────────┐
        │  REST    │ <────────────── │   WORK     │
        │ 回休息点 │                 │ 循环干活   │
        └──────────┘                 └────────────┘
```

- 状态用 `enum` + `match` 实现单文件状态机即可，**不引入第三方状态机插件**。
- `SEEK_WORK` 用 `NavigationAgent2D` 寻路（工程已有 2D 场景基础）。
- **降级方案（重要）**：如果 NavigationAgent2D 在整张 1014×1014 底图上烘焙/调参耗时超预期，立刻降级为 **AStarGrid2D + 路点直连**，保证 Demo 能跑通再谈手感。

### 4.4 餐厅系统

餐厅底图已有：`assets/sprites/backgrounds/restaurant.png`。

#### 每日菜单配置（玩家唯一每天都做的决策）

- 菜单有**格数上限**（初始 3 格，扩餐厅可加到 5/6 格）。
- 每格从"当前库存够做的菜"里选一道。
- **看不到库存就选不出好菜单**——所以菜单面板必须同时显示：食材库存、菜品成本、菜品售价、预估毛利。这是玩家决策质量的关键 UI。
- 菜单决定了：顾客点什么、消耗什么食材、当天能赚多少。

#### 营业阶段流程（90 秒）

```
点击「开始营业」
      │
      ▼
  顾客按时间轴生成（走进店 → 找空位坐下）
      │
      ▼
  入座 → 从今日菜单中"点单" → 生成订单（进入订单队列）
      │
      ▼
  厨师（厨房岗位员工）取订单 → 走到灶台 → 做菜（耗时，消耗食材）
      │
      ▼
  出菜窗口 → 服务员取菜 → 寻路送到对应顾客桌 → 上菜
      │
      ▼
  顾客用餐（固定时长）→ 走到收银台结账 → 付钱离店 → 座位释放
      │
      ▼
  座位/厨师/服务员 三者中任意一个成为瓶颈 → 排队 → 超出耐心 → 顾客不满离店
```

#### 瓶颈设计（放置类的"下一步该买什么"引导）

| 症状 | 玩家看到的 | 该花的钱 |
| --- | --- | --- |
| 大量顾客在门口等位 | 座位全满、门口排队 | 扩座位 |
| 订单堆在队列里没人做 | 灶台空着、订单列表变长 | 招厨师 / 加灶台 |
| 菜做好了没人送 | 出菜口堆菜、顾客耐心掉 | 招服务员 |
| 菜单只能上 3 道菜 | 菜单格数已满 | 扩餐厅 |
| 做菜时食材不够 | 菜品变灰 | 扩农场 / 招农工 |

#### 顾客与等待

- 顾客有**耐心值**（可视化进度条）。等待超过耐心值 → 愤怒离店，Demo 中对口碑有轻微影响（口碑只影响顾客数量，不做复杂模拟）。
- 口碑：Demo 用一个 0~100 的数值，影响顾客生成速率，**不做社交/评价系统**。

## 五、Demo 范围（MVP）

### 必须做（做不到就没有 Demo）

- [ ] 日循环状态机：早晨 → 营业 → 结算，可连续跑 3 天不崩
- [ ] 种地：播种 / 生长 / 每日收获（至少 2 种作物）
- [ ] 畜牧：饲料消耗 + 每日产出（至少 1 种动物）
- [ ] 钓鱼：自动积累 + 员工收取
- [ ] 员工：分配岗位 + 寻路 + 工作状态机 + 体力
- [ ] 餐厅：菜单配置 + 顾客生成 + 点单 + 做菜 + 上菜 + 结账
- [ ] 经济：蛙币、库存、日结算（营收 − 成本 − 工资）
- [ ] 商店：招员工、扩地、扩座位、买种子/动物
- [ ] UI：分配面板、菜单面板、商店面板、日结算面板
- [ ] 能完整玩 15 分钟，并在第 3 天做出一次"扩张"决策

### 明确不做（Demo 砍掉清单）

| 砍掉 | 原因 |
| --- | --- |
| 玩家操控角色 / 潜水 / 钓鱼小游戏 | 与"玩家不操作"的核心定位冲突 |
| 天气、季节、节日 | 系统成本高，体验增量低 |
| 剧情、对话、NPC 好感度 | Demo 不需要叙事 |
| 员工技能树、培养、离职 | 数值复杂度爆炸 |
| 多餐厅、多农场 | 内容量翻倍 |
| 复杂存档（多槽位/云存档） | Demo 只做单存档或不做 |
| 音乐音效 | 用占位音或静音 |
| 正式美术 | **统一用占位色块/现有素材**，美术后置 |

> ⚠️ **范围纪律**：Demo 阶段最大的风险不是技术，是范围。任何"顺手加个系统"的想法，先写进"Demo 后扩展"章节，不要当场实现。

## 六、技术方案（Godot 4.7 + GDScript）

### 6.1 架构原则

1. **数据驱动**：作物、动物、菜品、员工参数全部放 `data/*.tres`（自定义 `Resource`），策划改数值不改代码。
2. **信号解耦**：用 `EventBus`（Autoload）广播事件，系统之间不互相 `get_node`。
3. **UI 与逻辑分离**：UI 只读数据、发信号，不做业务计算。
4. **先垂直切片**：先把"1 块地 + 1 个员工 + 1 道菜"跑通，再横向加内容。

### 6.2 Autoload 单例

| 单例 | 职责 |
| --- | --- |
| `EventBus` | 全局信号总线：`money_changed` / `day_started` / `order_placed` / `staff_assigned` … |
| `GameClock` | 日阶段状态机、营业倒计时、速度控制 |
| `Economy` | 蛙币收支、日结算、工资扣除 |
| `Inventory` | 所有物品库存的增删查（统一入口，便于存档） |
| `StaffRegistry` | 员工实例注册表、岗位分配关系的唯一真相源 |
| `SaveManager` | 存/读档（`user://save.json`，用 JSON 或 `ConfigFile`） |

### 6.3 数据资源（`data/`）

```
data/
├── crops/      turnip.tres, lettuce.tres, wheat.tres, tomato.tres
├── animals/    chicken.tres, cow.tres
├── recipes/    fried_egg.tres, salad.tres, grilled_fish.tres, ...
├── staff/      frog_worker.tres
└── items/      item_*.tres（统一物品定义，供库存引用）
```

`CropData`（示例字段）：`id, display_name, icon, seed_cost, grow_days, yield_amount, sell_price, is_feed`

### 6.5 关键技术点

| 点 | 方案 |
| --- | --- |
| 寻路 | `NavigationRegion2D` + `NavigationAgent2D`；烘焙在 1014×1014 底图上手绘 `NavigationPolygon` |

```gdscript
# autoload/inventory.gd
extends Node
## 所有物品库存的唯一入口。key 用 String 而非 StringName，方便 JSON 存档。

var _items: Dictionary = {}   # item_id: String -> amount: int

func add(item_id: String, amount: int = 1) -> void:
	if amount <= 0:
		return
	_items[item_id] = get_amount(item_id) + amount
	EventBus.inventory_changed.emit(item_id, _items[item_id])

func consume(item_id: String, amount: int = 1) -> bool:
	if not has(item_id, amount):
		return false
	_items[item_id] = get_amount(item_id) - amount
	EventBus.inventory_changed.emit(item_id, _items[item_id])
	return true

func consume_many(stacks: Array[ItemStack]) -> bool:
	for s in stacks:                     # 先全部校验再扣，避免扣一半失败
		if not has(s.item_id, s.amount):
			return false
	for s in stacks:
		consume(s.item_id, s.amount)
	return true

func has(item_id: String, amount: int = 1) -> bool:
	return get_amount(item_id) >= amount

func get_amount(item_id: String) -> int:
	return int(_items.get(item_id, 0))

func to_dict() -> Dictionary:
	return _items.duplicate()

func from_dict(data: Dictionary) -> void:
	_items = data.duplicate()
	EventBus.inventory_reloaded.emit()
```

```gdscript
# autoload/economy.gd
extends Node
## 蛙币收支与日结算。所有加减钱必须走这里，不要直接改 money。

enum Category { REVENUE, INGREDIENT, WAGE, INVESTMENT }

var money: int = 500
var _totals: Dictionary = {}          # Category -> int

func can_afford(amount: int) -> bool:
	return money >= amount

func earn(amount: int, category: Category = Category.REVENUE) -> void:
	_apply(amount, category)

func spend(amount: int, category: Category = Category.INGREDIENT) -> bool:
	if not can_afford(amount):
		EventBus.toast.emit("蛙币不够")
		return false
	_apply(-amount, category)
	return true

func _apply(delta: int, category: Category) -> void:
	money += delta
	_totals[category] = int(_totals.get(category, 0)) + (delta if delta > 0 else -delta)
	EventBus.money_changed.emit(money, delta)

func settle_day(day: int) -> DayReport:
	var report := DayReport.new()
	report.day = day
	report.revenue = int(_totals.get(Category.REVENUE, 0))
	report.ingredient_cost = int(_totals.get(Category.INGREDIENT, 0))
	report.wages = int(_totals.get(Category.WAGE, 0))
	report.investment = int(_totals.get(Category.INVESTMENT, 0))
	report.cash_after = money
	_totals.clear()
	return report
```

```gdscript
# autoload/game_clock.gd
extends Node
## 日循环状态机。注意：不使用 Engine.time_scale，速度只影响本节点的累加。

const BUSINESS_DURATION := 90.0

var day: int = 1
var phase: DayPhase.Phase = DayPhase.Phase.MORNING
var time_left: float = 0.0
var speed: float = 1.0

func _ready() -> void:
	# 首日广播延后一帧，避免与其它节点的 _ready 顺序竞争
	call_deferred("_begin_morning")

func _process(delta: float) -> void:
	if phase != DayPhase.Phase.BUSINESS:
		return
	time_left -= delta * speed
	EventBus.business_time_changed.emit(time_left, BUSINESS_DURATION)
	if time_left <= 0.0:
		_end_business()

func start_business() -> void:
	if phase != DayPhase.Phase.MORNING:
		return
	if not _has_anything_to_sell():
		EventBus.toast.emit("今日菜单是空的，先配置菜单")
		return
	_set_phase(DayPhase.Phase.BUSINESS)
	time_left = BUSINESS_DURATION
	EventBus.business_started.emit()

func _end_business() -> void:
	_set_phase(DayPhase.Phase.CLOSING)
	_pay_wages()
	var report := Economy.settle_day(day)
	EventBus.business_ended.emit(report)     # UI 弹结算面板，等玩家点「进入下一天」

func next_day() -> void:
	if phase != DayPhase.Phase.CLOSING:
		return
	day += 1
	_begin_morning()

func _begin_morning() -> void:
	_set_phase(DayPhase.Phase.MORNING)
	EventBus.day_started.emit(day)           # 农田/畜栏/钓点在这里结算

func _set_phase(next: DayPhase.Phase) -> void:
	phase = next
	EventBus.phase_changed.emit(phase)

func _pay_wages() -> void:
	for w in StaffRegistry.workers:
		Economy.spend(w.data.wage, Economy.Category.WAGE)

func _has_anything_to_sell() -> bool:
	return not RestaurantService.menu.is_empty()
```

```gdscript
# autoload/staff_registry.gd
extends Node
## 员工实例与岗位分配的唯一真相源。

@export var worker_scene: PackedScene      # 在 _ready 里从 res:// 载入亦可

var workers: Array[Worker] = []
var slots: Array[JobSlot] = []

func register_worker(worker: Worker) -> void:
	workers.append(worker)

func unregister_worker(worker: Worker) -> void:
	workers.erase(worker)

func register_slot(slot: JobSlot) -> void:
	slots.append(slot)

func assign(worker: Worker, slot: JobSlot) -> bool:
	if slot != null and not slot.is_free() and slot.assigned_worker != worker:
		EventBus.toast.emit("这个岗位已经有人了")
		return false
	worker.assign_to_slot(slot)            # 内部负责释放旧岗位
	return true

func unassign(worker: Worker) -> void:
	worker.assign_to_slot(null)

func free_slots() -> Array[JobSlot]:
	return slots.filter(func(s: JobSlot) -> bool: return s.is_free())

func hire(data: StaffData, spawn_point: Vector2) -> Worker:
	if not Economy.spend(data.hire_cost, Economy.Category.INVESTMENT):
		return null
	var worker: Worker = worker_scene.instantiate()
	worker.data = data
	worker.global_position = spawn_point
	get_tree().current_scene.add_child(worker)
	register_worker(worker)
```

```gdscript
# scripts/staff/worker.gd
class_name Worker
extends CharacterBody2D

enum State { IDLE, SEEK_WORK, WORK, REST }

const ARRIVE_DISTANCE := 6.0
const REST_RECOVER_RATE := 25.0     # 每秒恢复体力
const IDLE_RECHECK := 0.5           # 待命时多久看一眼岗位有没有活

@export var data: StaffData
@export var home_point: Vector2 = Vector2.ZERO

var stamina: float = 100.0
var assigned_slot: JobSlot = null

@onready var agent: NavigationAgent2D = $NavigationAgent2D
@onready var sprite: AnimatedSprite2D = $AnimatedSprite2D

var _state: State = State.IDLE
var _work_timer: float = 0.0
var _idle_timer: float = 0.0

func _ready() -> void:
	add_to_group("workers")
	if data == null:
		push_error("Worker 缺少 StaffData")
		return
	stamina = data.max_stamina
	home_point = home_point if home_point != Vector2.ZERO else global_position

func _physics_process(delta: float) -> void:
	match _state:
		State.IDLE:      _tick_idle(delta)
		State.SEEK_WORK: _tick_seek_work(delta)
		State.WORK:      _tick_work(delta)
		State.REST:      _tick_rest(delta)

# ---------- 外部接口（玩家分配岗位的唯一入口） ----------

func assign_to_slot(slot: JobSlot) -> void:
	if assigned_slot == slot:
		return
	if assigned_slot != null:
		assigned_slot.release(self)
	assigned_slot = slot
	if slot != null:
		slot.claim(self)
		_change_state(State.SEEK_WORK)
	else:
		_change_state(State.IDLE)

# ---------- 状态实现 ----------

func _change_state(next: State) -> void:
	_state = next
	_work_timer = 0.0
	_idle_timer = 0.0

func _tick_idle(delta: float) -> void:
	velocity = Vector2.ZERO
	move_and_slide()
	_play_anim(false)
	_idle_timer -= delta
	if _idle_timer > 0.0:
		return
	_idle_timer = IDLE_RECHECK
	if assigned_slot != null and assigned_slot.can_work():
		_change_state(State.SEEK_WORK)

func _tick_seek_work(delta: float) -> void:
	if assigned_slot == null or not assigned_slot.can_work():
		_change_state(State.IDLE)
		return
	if _move_towards(assigned_slot.get_work_point(), delta):
		_change_state(State.WORK)

func _tick_work(delta: float) -> void:
	if assigned_slot == null:
		_change_state(State.IDLE)
		return
	velocity = Vector2.ZERO
	move_and_slide()
	_play_anim(false)

	_work_timer += delta * data.work_speed
	stamina -= data.stamina_drain * delta

	if _work_timer >= assigned_slot.get_work_seconds():
		assigned_slot.perform_work(self)
		_work_timer = 0.0
	if stamina <= 0.0:
		_change_state(State.REST)

func _tick_rest(delta: float) -> void:
	stamina = min(stamina + REST_RECOVER_RATE * delta, data.max_stamina)
	if not _move_towards(home_point, delta):
		return
	if stamina >= data.max_stamina:
		_change_state(State.SEEK_WORK if assigned_slot != null else State.IDLE)

# ---------- 寻路与表现 ----------

## 返回 true 表示已到达目标
func _move_towards(point: Vector2, _delta: float) -> bool:
	agent.target_position = point
	var dir := global_position.direction_to(agent.get_next_path_position())
	if agent.is_navigation_finished() or global_position.distance_to(point) <= ARRIVE_DISTANCE:
		velocity = Vector2.ZERO
		move_and_slide()
		_play_anim(false)
		return true
	velocity = dir * data.move_speed
	move_and_slide()
	_play_anim(true, dir)
	return false

func _play_anim(walking: bool, dir: Vector2 = Vector2.ZERO) -> void:
	if walking and absf(dir.x) > 0.01:
		sprite.flip_h = dir.x > 0.0
	sprite.play("walk" if walking else "idle")
```

> ⚠️ **现有动画名要改**：`character_body_2d.tscn` 里现在只有 `frog_walk_left` 和 `frog_dle_right`（后者疑似 `idle` 拼写错误），
> 且只有两个方向。上面代码用的是 `idle` / `walk` + `flip_h` 翻转的方案。

### 11.11 写代码时的注意事项

1. **不要在 `_ready()` 里做跨系统的初始化**：autoload 的初始化顺序不完全可控，跨系统的事放到 `call_deferred` 或监听 `day_started`。
2. **所有钱的加减必须过 `Economy`**，否则日结算数字会错。
3. **所有物品的加减必须过 `Inventory`**，否则 UI 不刷新。
4. **`Order` 挂在 `OrderQueue` 下而不是顾客下**：顾客愤怒离店后订单还需要被厨房清理，挂队列更安全。
5. **顾客/动物/田地都要 `add_to_group`**，方便 `RestaurantService._clear_customers()` 和存档收集。
6. **随机数用 `RandomNumberGenerator` 实例，不要用全局 `randi()`**：可设 `seed` 复现 Bug。
7. **数值不要写死在脚本里**（`cook_time`、`wage` 等一律走 `.tres`），M4 调平衡时你会感谢自己。
8. 上面的代码**故意留了简化**（服务员原地送菜、顾客直线走入、钓鱼无小游戏），都是企划第五章范围纪律的一部分，不要顺手补全。
9. **当心脚本循环引用**：`Worker` / `JobSlot` / `Order` / `FieldPlot` 这些类既要被 `EventBus` 引用，又反过来用 `EventBus`。
   本项目统一约定：**EventBus 的信号参数一律用无类型标注**（见 11.5 的注释），只靠注释说明类型，规避 Godot 的 "Cyclic reference" 解析错误。
   如果哪个类报循环引用，第一反应是把它的类型标注改成无类型，而不是拆类。
10. **Autoload 脚本不要写 `class_name`**（如 `RestaurantService`）：autoload 名与全局类名同名会冲突。Autoload 名字本身就能当全局标识符用。
11. `RestaurantService` 被 `GameClock` 直接引用（判断菜单是否为空），这是**故意允许的例外**：作为"营业流程"的门面，它需要被时钟查询。
    其余跨系统通信仍然一律走信号。
